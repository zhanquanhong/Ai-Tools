# 🐞 BUG 处理进展跟踪系统 v1.41.0

用于跟踪管理开发团队每天的 BUG 处理进展：**新增多少、解决多少、谁在处理**。
每天导入一次 BUG 列表（.xlsx/.csv），自动对比上次快照，统计新增/解决/重新激活，支持责任人改派、手动状态调整与全程追溯。

**架构**：Python 后端（`server.py`）+ 浏览器前端，数据存服务端 `data/state.json`，支持多账号登录与权限分级（管理员/普通用户）。

---

## 一、快速开始

1. **配置账号**：编辑 `auth.json`，按 `{"accounts": {"用户名": {"pass": "密码", "role": "admin|user"}}}` 格式配置登录账号（至少一个 admin）
2. **启动服务**：
   ```bash
   ./start_server.sh        # 或手动：python3 -u server.py 8092
   ```
3. **打开工具**：浏览器访问 `http://服务器IP:8092`（默认端口 8092，可在 server.py 的 `DEFAULT_PORT` 修改）
4. **首次使用**：登录后点击「📥 导入 BUG」→ 拖入或选择 BUG 列表文件（.xlsx/.xls/.csv）→ 确认字段映射 → 点击「确认导入」
5. **日常使用**：每天导入一次最新 BUG 列表，工具自动对比出：
   - 🆕 **新增**：本次新出现的编号
   - ✅ **解决**：本次消失的编号（**已解决的 BUG 不会出现在导入列表中，消失即视为解决**）
   - 🔄 **重新激活**：曾解决又出现的编号
   - 👤 **责任人变更**：同编号责任人变化（自动记录上次责任人）

> ⚠️ **注意**：首次导入为基线快照，全部记为新增，无对比结果。

## 二、界面功能

### 🔐 登录与权限
- 多账号登录，会话保持（Cookie），未登录访问自动跳转登录页
- 角色分级：**管理员**（全部功能 + 版本管理/备份/回滚 + 查看登录记录）+ **普通用户**（导入/看板/列表/人员管理，版本管理只读）
- 登录成功/失败均记录到「🛡️ 登录记录」（时间/IP/账号/结果），仅管理员可见

### 📥 导入 BUG
- 支持 `.xlsx` / `.xls` / `.csv`，自动识别 GBK / UTF-8 / UTF-16 编码
- 自动匹配列名，可手动调整字段映射（「编号」为必映射主键）
- 导入结果展示：新增 / 解决 / 重新激活 / 责任人变更 / 跳过数量
- **漏导防护**：单次解决数超过存量 30% 时告警，防止漏导导致误判
- **标题同步**：同编号 BUG 标题以最新导入为准更新（描述/创建人保留系统值），标题变更写入导入历史明细
- **严重程度跟随**：严重程度以最新导入为准（可能被重新评估），变更明细记录可追溯
- **原始负责人保护**：已分配（责任人非原始名单）的 BUG，重新导入原始负责人名单时不覆盖

### 📊 每日看板
- 统计卡片：今日新增 / 今日解决 / 未解决总数 / 停留超期（阈值可调，默认 ≥5 天）
- 统计口径：一天多次导入按**当天累计**计算；「较昨日」= 今日累计 vs 上一导入日累计（跨天自动识别，显示对比日期）
- 按「发现发布」版本统计（问题数 + 占比，**点击可联动筛选列表**）
- 按「严重程度」统计（严重 / 一般 / 轻微，自动按导入数据生成）
- 近 7 / 14 / 30 / 60 / 90 日新增/解决趋势图（天数可选，自动保存）
- 责任人维度：各人名下未解决数、超期数（**点击人员联动看板版本筛选**）
- 「📊 问题统计」弹窗：按看板所选版本统计问题总计与严重程度分布，一键复制（截止最后导入时间口径）

### 📋 BUG 列表
- 展示全部字段，**每一列都可筛选**：
  - 枚举列（状态/严重程度/责任人/版本…）→ 下拉多选（支持「全选/清空」快捷操作）
  - 文本列（标题/描述/编号…）→ 关键词搜索
  - 数值列（停留天数）→ 范围筛选
  - 时间列（最近修改时间…）→ 日期范围
- 顶部快速搜索（编号/标题/描述等全字段）+「🆕 今日新增」快捷筛选按钮（与看板卡片口径一致）
- 行内操作：
  - **改派**：将 BUG 分配给其他责任人（需在人员名单中）
  - **备注**：添加/修改处理进展说明（独立于导入数据，重新导入不覆盖，记录操作人与时间）
  - **状态调整**：手动关闭 / 重新打开（二次确认，联动看板统计按操作日期记账）
  - **历史**：查看责任人变更轨迹与删除记录
  - **删除**：删除不属于本团队的 BUG（需填写原因，必填），删除记录写入变更历史可追溯
- 导出当前筛选结果（.csv）；「导出清单」仅导出待跟进问题（已手动关闭的不导出）

### 👥 人员管理
- 新增 / 重命名 / 删除人员
- 导入时出现的新责任人**自动加入名单**
- 删除保护：名下有未解决 BUG 时禁止删除，需先改派

### 💾 数据备份与版本管理
- **完整备份导出**（.xlsx，多 Sheet）：BUG 列表（含系统字段）/ 变更历史 / 人员名单 / 快照记录 / 原始负责人名单
- **从备份恢复**：选择备份文件 → 确认（恢复前自动备份当前数据）→ 完整还原
- **版本管理页**（仅管理员）：
  - 启动自动备份：服务启动检测到代码变更自动打包备份，保留最近 **7 天**，超期自动清理
  - 「立即备份」：升级部署前一键备份当前版本，出问题可回滚
  - 一键回滚：管理员选择备份 → 二次确认 + 后端双重校验 → 回滚代码文件（**不影响 BUG 数据**），回滚前自动备份当前版本
  - 备份列表展示版本号 / 来源 IP / 时间点，操作留痕写入 `data/backup-log.json`
- **更新日志**：点击标题栏版本号查看（版本 + 日期时间 + 更新来源 IP），所有登录用户只读

## 三、数据存储说明

| 项目 | 说明 |
|------|------|
| 存储位置 | 服务端 `data/state.json`（原子写入，多端共享） |
| 保留时间 | 永久（随服务器磁盘） |
| 更新工具文件 | **不影响数据**（数据在服务端 data/，不在代码文件中） |
| 丢失风险 | 服务器磁盘损坏 / 手动删除 data/ |
| 并发安全 | 读写加锁，原子写入防损坏 |

**建议**：重要节点（版本升级前、大批量导入前）先「📦 版本管理」页点「立即备份」+ 导出完整备份。

## 四、版本管理

- 工具标题栏与页脚显示当前版本号，点击版本号查看「更新日志」（存于 `data/changelog.json`，发版时写入新条目）
- 版本规则：修复 Bug → 小版本 +1（v1.0.1）；新功能 → 中版本 +1（v1.1.0）；重大重构 → 大版本 +1（v2.0.0）
- 版本升级不迁移数据，旧数据无缝沿用

> ⚠️ **升级标准流程**：①「版本管理」页点「立即备份」→ ② 替换代码文件 → ③ 重启服务（自动再备份新版本）→ ④ 出问题在「版本管理」页回滚。
>
> ⚠️ **注意**：服务器无法感知"文件被外部替换"的动作，升级前的旧版本只能在替换前备份（立即备份按钮）。启动自动备份记录的是替换后的新版本。

## 五、核心规则（业务约定）

| 规则 | 说明 |
|------|------|
| 已解决不出现 | 已解决的 BUG 不在导入列表中 → **消失即解决** |
| 编号为主键 | 同编号为同一 BUG，跨快照对比 |
| 责任人导入覆盖 | 每次导入以最新列表的责任人为准（原始负责人名单保护除外） |
| 上次责任人 | 自动记录当前责任人的上一个值，可追溯 |
| 重新激活 | 曾解决又出现的 BUG，标记重新激活，不计入新增 |
| 状态/严重程度/版本 | 均以导入数据动态生成，不写死 |

## 八、常见问题

**Q：导入 CSV 中文乱码？**
A：工具自动检测 GBK/UTF-8 编码，无需手动设置。若仍有乱码，请确认文件非 UTF-16 特殊编码。

**Q：导入时提示"未找到编号列"？**
A：请在字段映射中手动指定「编号」列，它是对比的主键。

**Q：提示解决数异常（超 30%）？**
A：可能漏导或列表不完整，请检查文件后重新导入；如确为正常，可忽略继续。

**Q：换服务器数据怎么带过去？**
A：旧服务器「导出完整备份」→ 新服务器部署后 →「从备份恢复」；或直接拷贝 `data/state.json`。

**Q：版本升级会丢数据吗？**
A：不会。数据存在服务端 `data/state.json`，与代码文件版本无关。

**Q：忘记管理员密码？**
A：直接编辑服务器上的 `auth.json` 重置。

## 九、改动保护规范（2026-08-15 起强制）

**背景**：v1.20.0 加列宽拖拽时引入 `table-layout:fixed`，导致操作列按钮被 CSS 裁切（textContent 断言查不出视觉问题）。

**铁律（每条改动必须遵守）**：

1. **改动前**：列出「动的文件 + 影响的模块」清单。改共享类/共享函数前必须 grep 确认使用者（如 `.data-table` 被 bug 表/人员表/登录记录表共用）。
2. **样式隔离**：新样式一律用 `#bugTable` 等 ID 限定，禁止改共享类全局属性（table-layout / display / position 等）。确需改共享类时，用 ID 选择器覆盖回来并跑全量冒烟。
3. **几何可见性**：涉及布局/CSS 的改动，冒烟测试必须包含 `vis()`（offsetWidth/offsetHeight > 0）断言——textContent 查不到"被裁切/被隐藏"，几何查得到。
4. **全量门禁**：每次上线前必跑（不是只跑新功能断言）：
   ```bash
   node test/build-ui-smoke.js
   google-chrome --headless --disable-gpu --no-sandbox --virtual-time-budget=8000 --dump-dom "file://$PWD/test/ui.smoke.html"
   # 标题必须为 SMOKE-ALL-PASS
   node test/engine.test.js && node test/storage.test.js && python3 test/test_backup.py
   ```
5. **回滚预案**：上线前备份被改文件（`cp js/app.js /tmp/app.js.$(date +%s).bak`），出问题 1 分钟还原。
6. **范围最小化**："你让改什么就只改什么"——不附带任何未提及的改动；不确定先问。
